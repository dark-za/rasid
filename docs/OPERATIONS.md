# تشغيل وصيانة راصد

## كيف تُخزّن البيانات

- يخزّن راصد الورديات والموظفين والإسنادات في قاعدة SQLite محلية واحدة. افتراضياً الملف هو `backend/data/rasid.sqlite3`، وينشأ تلقائياً عند تشغيل backend.
- في Docker يوجد الملف وبيانات اتصال SmartPSS في الحجم الدائم `rasid-data`. لا تحذف هذا الحجم عند تحديث التطبيق.
- يتصل راصد بقاعدة SmartPSS الخارجية للقراءة من `AttendanceRecordInfo` فقط. جلب الموظفين يتم بطلب المشرف، وتُحفظ القائمة بعد ذلك محلياً في SQLite.
- الاتصال الخارجي يضبط من صفحة المشرف أو بمتغيرات `DB_HOST`, `DB_PORT`, `ATTENDANCE_DB_NAME`, `ATTENDANCE_DB_USER`, `ATTENDANCE_PASS`. كلمة مرور الاتصال تُحفظ كنص إعداد محلي عادي في `.db-runtime.env`؛ احمِ صلاحيات الوصول إلى الملف ومجلد البيانات.
- يحتفظ راصد ببياناته حتى عندما يكون مصدر SmartPSS غير متصل؛ الحضور يحتاج اتصال المصدر، بينما بيانات الورديات والموظفين المخزنة محلياً تبقى متاحة.

## التشغيل

1. انسخ `.env.example` إلى `.env`.
2. ضع `RASID_LOGIN_PASSWORD` وسر جلسة `RASID_SESSION_SECRET`.
3. شغّل `docker compose up --build -d` أو اتبع خطوات التشغيل المحلي في [README](../README.md).
4. افتح صفحة المشرف، أدخل اتصال SmartPSS، اختبره واحفظه.
5. اضغط **جلب الموظفين من قاعدة البصمة** لاستيراد الأرقام والأسماء وتخزينها محلياً.

لا يلزم إنشاء قاعدة MySQL لراصد أو إنشاء مستخدم ترحيل أو تشغيل Alembic.

## النسخ الاحتياطي والاستعادة

يوفر راصد سكربت نسخ احتياطي آمن وتلقائي `backend/backup.py` يستخدم ميزة `sqlite3.backup` لأخذ نسخة متسقة دون إيقاف الخدمة، مع فحص سلامة الملف (`PRAGMA integrity_check`) والاحتفاظ بآخر N نسخة (افتراضياً 7 نسخ):

### التشغيل المحلي:
```bash
# تشغيل السكربت بالخيارات الافتراضية (يحفظ في backend/backups مع الاحتفاظ بآخر 7 نسخ):
python backend/backup.py

# تحديد مسارات مخصصة وعدد النسخ:
python backend/backup.py --source backend/data/rasid.sqlite3 --dest /path/to/backups --keep 14
```

### التشغيل عبر Docker:
```bash
# تنفيذ النسخ الاحتياطي داخل حاوية الباكند:
docker compose exec backend python backup.py --source /var/lib/rasid/rasid.sqlite3 --dest /var/lib/rasid/backups --keep 7
```

يمكن جدولة هذا الأمر دورياً (عبر `cron` على Linux أو Task Scheduler على Windows) لأخذ نسخ يومية تلقائياً.

في حال الاستعادة، يكفي استبدال ملف قاعدة البيانات النشط بنسخة احتياطية سليمة بعد إيقاف الخدمة مؤقتاً. اختبر الاستعادة على بيئة منفصلة قبل استبدال بيانات التشغيل.

## ملاحظات عن الانتقال من قاعدة راصد القديمة

إذا كان إصدار سابق قد حفظ الورديات أو الإسنادات في MySQL `rasid_db`، فلن يحذف التغيير هذه القاعدة، لكنه يبدأ ملف SQLite محلياً جديداً ولا ينسخ السجلات القديمة تلقائياً. أبقِ قاعدة MySQL القديمة ونسختها الاحتياطية إلى أن تقرر ترحيل بياناتها. قاعدة SmartPSS الخارجية لا تتغير.

## استمرار الخدمة

- يستخدم SQLite وضع WAL مع مهلة انتظار قصيرة للتعامل مع القراءات والكتابات المتزامنة المعتادة.
- تحقق من `GET /health/live` لحياة العملية و`GET /health/ready` لجاهزية SQLite ومصدر البصمة.
- عند توقف SmartPSS، تظهر أخطاء الحضور بوضوح، وتظل إدارة البيانات المخزنة محلياً متاحة.
- لوحة القراءة العامة تعرض أسماء الموظفين وأرقامهم وسجلات الحضور؛ شغّل الموقع داخل شبكة الشركة أو VPN فقط.
