# راصد — نظام متابعة الحضور والانصراف

نظام لمتابعة حضور موظفي الفروع من أجهزة البصمة SmartPSS، مع واجهة ويب للعرض وإدارة إسناد الموظفين للفرع.

## المكوّنات

| المكوّن | التقنية | الوصف |
|---|---|---|
| `backend/` | FastAPI + SQLAlchemy + PyMySQL | واجهة برمجية للحضور والورديات وإسناد الفروع |
| `frontend/` | React 18 + Vite | واجهة عرض (تُبنى إلى `frontend/dist`) |
| قاعدة بيانات النظام `rasid_db` | MySQL | جداول النظام (`shifts`, `employee_branch_history`) — تُنشأ تلقائياً |
| قاعدة البصمة `smartpss_local` | MySQL | جدول `AttendanceRecordInfo` — **قراءة فقط**، لا يُمسّ مخطّطها |

## المتطلبات

- Python 3.10+ (يُستخدم 3.12 محلياً و3.10 في صورة Docker)
- Node.js 18+
- MySQL 8 يقبل اتصالات من التطبيق

## الإعداد الأول

```bash
# 1) انسخ ملف الإعدادات في الجذر واملأ القيم
cp .env.example .env

# 2) ولّد مفتاح تشفير الأسرار ومفتاح واجهة API
python -m security genkey          # أو: cd backend && python -m security genkey
python -c "import secrets;print(secrets.token_urlsafe(32))"   # مفتاح RASID_API_KEY

# 3) عبّئ RASID_SECRETS_KEY في .env ثم شفّر كلمة سر قاعدة البيانات
RASID_SECRETS_KEY=<المفتاح> python -m security encrypt 'كلمة-سر-MySQL'
# الناتج (DB_PASS_ENC) يوضع في .env — لا تضع كلمة السر الصريحة في الإنتاج
```

## التشغيل المحلي

```bash
# الباكند
cd backend
python -m venv venv && venv/bin/pip install -r requirements.txt
venv/bin/uvicorn main:app --host 127.0.0.1 --port 8000

# الواجهة (تطوير — تُحوّل طلبات /api إلى الباكند على 8000)
cd frontend
npm install
npm run dev        # http://localhost:3005
```

## التشغيل بـ Docker

```bash
docker compose up --build -d      # الباكند على المنفذ 8000
```

`docker compose` يقرأ `.env` من الجذر تلقائياً لاستبدال المتغيّرات.

## واجهة API

جميع المسارات المحمية تتطلب رأس `X-API-Key` (المفتاح من `RASID_API_KEY`)؛ غيابه أو خطؤه = `401`، وغياب الإعداد = `503`.

| المسار | الوصف |
|---|---|
| `GET /` | صحة النظام ووقت التشغيل الحالي (بلا مصادقة) |
| `GET /api/attendance/today` | بصمات اليوم: السجلات بعد فلترة التبصيم المتكرر + قائمة المتأخرين |
| `GET /api/shifts` | الورديات (ينشئ وردية افتراضية 08:00–17:00 بسماح 15 دقيقة إن لم تكن هناك وردية) |
| `GET /api/employee-branches?limit=50&offset=0` | سجلات إسناد الموظفين (ترقيم صفحات) |
| `POST /api/employee-branches` | نقل موظف إلى فرع — يرفض التداخل بـ `409` |

مثال:

```bash
curl -H "X-API-Key: $RASID_API_KEY" http://127.0.0.1:8000/api/attendance/today
```

جسم طلب `POST /api/employee-branches`:

```json
{
  "employee_id": "16",
  "employee_name": "سالم",
  "branch_name": "فرع العليا",
  "start_date": "2026-11-01"
}
```

## منطق الحضور

- **فلترة التبصيم المتكرر (debounce):** بصمتان لنفس الموظف في المدة `DEBOUNCE_MINUTES` (الافتراضي 5 دقائق) تُحتسبان بصمة واحدة (الأولى).
- **التأخير:** حضور بعد بداية الوردية + سماح `grace_period_minutes` يعدّ متأخراً (دقائق التأخير = الفرق الفعلي عن بداية الوردية). بصمات ما بعد منتصف الليل لا تُعدّ متأخرة.
- **التوقيت (`APP_TIMEZONE`، الافتراضي `Asia/Riyadh`):** حساب «اليوم» وحدوده ومنتصف الليل والتأخير كله بتوقيت التطبيق.

### نمط فهم توقيت البصمة (`ATTENDANCE_EPOCH_IS_LOCAL`)

عمود `AttendanceDateTime` يُخزَّن كـ epoch بليغي. المتغيّر يحدد معناه:

- `true` (الافتراضي، **موافق للبيانات الحالية**): الرقم هو **وقت محلي مُرمَّز كـ epoch**. تحقّق في بياناتك: الفرق بين `AttendanceDateTime` و `AttendanceUtcTime` ثابت `+10800` ثانية (3 ساعات) في كل الصفوف تقريباً → الرقم محلي.
- `false`: الرقم **UTC حقيقي**. اختره فقط إذا كان العمود يساوي `AttendanceUtcTime` فعلياً.

تغيير هذه القيمة يؤثر مباشرة على حدود اليوم المعروضة وساعات البصمات.

## الأمان

- **لا ترفع `.env` إلى Git** — مُضاف إلى `.gitignore`. `.env.example` يحوي قوالب فقط.
- كلمة سر قاعدة البيانات تُخزَّن مشفّرة (Fernet) في `DB_PASS_ENC`؛ المفتاح `RASID_SECRETS_KEY` يُدار خارج المستودع في الإنتاج.
- إن كان مستودعك يحوي إعدادات قديمة في سجل Git (مثل كلمات سر قديمة) — **غيّرها فعلياً** على الخادم؛ حذف الملف من الـ commit الأخير لا يمحوها من السجل.
- قاعدة البصمة تُقرأ فقط: لا أنشطة كتابة ولا تعديل مخطّط عليها.

## ملاحظات الترحيل

- الجداول القديمة `CHECKINOUT` غير مستخدمة — المصدر الحالي هو `AttendanceRecordInfo`.
- «اليوم» يُحسب بحدود حصرية `[منتصف الليل، منتصف الليل التالي)` بتوقيت التطبيق؛ الوضع القديم كان يحسبها بتوقيت UTC/الحاوية مما يستبعد بصمات الصباح الباكر أو يضيف أمسيات الأمس.
